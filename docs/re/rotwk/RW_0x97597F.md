# RW 0x97597F — lobby minimum-player query (S-3610)

## Identity / offsets

Paired with [RW 0x9758E3](RW_0x9758E3.md), on the map/scenario preview
controller at MpGameSetup +0x60. Mode +0x1C equals MpGameSetup +0x7C.
The holder at +0x18 and scenario pointer chain are identical to that query;
the final field here is +0x14, not maximum's +0x10. The **minimum** meaning is
proven by start-check use; the original class/method/field spellings are unknown.
Calling the last record a Living World scenario remains **INFERENCE**, as in
the paired document. Supplied pack and direct target instructions are the
evidence, subject to PLAN rule 9 / S-001's modified-image caveat.

Every failing guard returns exactly zero; the validated GameInfo is not otherwise
read. No map lookup occurs, even outside strategic mode. The final dword is
returned without clamping or a nonnegative check. No floating point. The only
possible write is inside RW 0x83FF11: failed holder validation clears its +8
value. See the paired recovery for the checked tier-B donor and true boundary.
The method itself does not tolerate a null this or null holder +0x18.

## Callers / timing and port disposition

Pack references: RW 0x841E26 within lobby update RW 0x841D47, and RW 0x84326D
within MpGameSetup start check RW 0x8431B8. At start, the maximum has already
been clamped to eight and rejected if <=0. Minimum greater than maximum is an
immediate silent refusal; later too few users produces LAN:TooFewPlayers.
These signed comparisons are caller policy, not part of this getter.

The port's constant zero is correct only for the non-strategic / missing-context
paths. A nonnull selected scenario is not represented yet, so no fabricated
minimum is introduced. S-3610 stays open for scenario selection/ownership,
minimum/maximum data and faction restrictions. Once those types exist, add tests
with minimum > maximum, users < minimum, users == minimum, and a non-strategic
mode that ignores scenario data. No engine or simulation behavior changed and
no pinned hash vectors changed in this documentation-only commit.
