# RW 0x940435 — ControlBar::processCommandUI production cancellation

## Scope and provenance

This recovery covers the remaining S-3951 cancel-all flag, not the entire
dispatcher. Ghidra 12.1.2 decompile, disassembly and callers were read from the
supplied RotWK image. It contains the modified `stxt*`, `.mackt`, `.danetta`
sections (S-001); this is not a claim of independently verified clean-retail parity.
The private executable, project and raw analysis are not committed.

The map identifies a tier B edited counterpart, BFME2 0x939A65,
`ControlBar::processCommandUI` in `ControlBarCommandProcessing.cpp`. Its local
view calls the template field `hero`; that name is misleading. The RotWK INI
row at 0xDA46B8 names **MaxSimultaneousOfType**, parser 0x42EC11, offset 0x5F0,
and the instruction at 0x940CD0 reads a **word**. The embedded field table and
the existing `BuildAssistant::maxSimultaneousOfType` preserve that unsigned-16
contract. A finite cap of any value prevents bulk cancellation, not just heroes.

## Caller, ownership and timing

Ghidra callers are RW 0x8232ED and 0x941B9F. The existing control-bar window
route invokes this dispatcher for a command-button press; a secondary press
takes the cancellation arm at RW 0x940C57. The object must have a production
interface, the button must be CANCELABLE, and the object's controlling player
must be local. REVIVE shares the production arm but supplies its hero-record
index rather than a template ID (ThingTemplate +0x5E8).

The keyboard query occurs while the message is constructed, **not** when the
simulation later consumes it. RW 0x63F122 maps identically to `Keyboard::isShift`.
The port carries modifiers through both radial presses and Palantir callbacks;
a deferred callback captures Shift before waiting for the logic worker.

## Recovered cancellation tail

```cpp
// RW 0x940C78..0x940CB2: MSG_CANCEL_UNIT_CREATE (0x418)
GameMessage *message = TheMessageStream->appendMessage(MSG_CANCEL_UNIT_CREATE);
message->appendBooleanArgument(revival);
message->appendIntegerArgument(revival ? revivalID : what->getTemplateID());
// RW 0x940CB7..0x940CE2
bool all = TheKeyboard->isShift() && !revival && what
    && what->getMaxSimultaneousOfType() == 0;
message->appendBooleanArgument(all);
```

The accessor spelling above expresses the proven field rather than a recovered
C++ symbol. Decisive instructions: `cmp word ptr [edi+0x5f0],0` at 0x940CD0;
nonzero, no Shift, null template, or REVIVE clears the flag at 0x940CDE.

## Port and acceptance

`ControlBar::cancelQueued` emits the recovered flag, using the existing logic
consumer and refund behavior. Normal right press remains a single cancel;
REVIVE always remains by-index/single even with Shift. Both input surfaces
carry Shift. Retail HUD tests queue three units and exercise the Palantir with
no Shift, left Shift and right Shift; the existing radial hero-refund test now
holds Shift. No pinned vectors are changed. Simulation results can change for
Shift-right-click input that previously cancelled only one unit.

Other dispatcher gaps remain under their own stops; this does not claim their
closure or alter left-click batch production.
