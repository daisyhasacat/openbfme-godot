# RW 0x70E013 — Object::getDrawable (S-852)

## Evidence / boundaries

The supplied pack's 24-byte inventory extent is **not** the callable body:
RW 0x70E013 loads `[ecx+0x84]`, RW 0x70E019 returns. The next instruction at
RW 0x70E01A begins another function (an integer-to-float setter of +0x88).
Thus the reachable getter is seven bytes. Verified against the supplied image;
PLAN rule 9 / S-001 provenance caveat applies (modified extra sections present).

This is an Object getter, not an AI operation or a hero-record operation.
The BFME2 byte-matched source
`Code/GameEngine/Source/GameLogic/Object/ObjectRva0028D481.cpp` declares
`Object::m_drawable` at +0x84 and uses it in `replaceModelConditionFlags`.
The receiver in the hero creation caller is the newly created Object.
`getDrawable` is the ZH spelling; the supplied map has no BFME2 entry for this
particular getter, so the original RotWK symbol spelling is **INFERENCE**.

```cpp
// RW 0x70E013..0x70E019: no branch, side effect, allocation or float operation.
Drawable *Object::getDrawable() const
{
    return m_drawable; // Object +0x84; may be null
}
```

## Callers / when it runs

There are many ordinary client uses: RW 0x6CC915 calls at 0x6CCAA9 / 0x6CCBD3
before weapon FX; RW 0x5F1B5A calls repeatedly for bone/FX transforms;
RW 0x678C69 calls at 0x678DD4 / 0x678E80 while updating the drawable.
The pack's reference list omits a relevant caller: direct disassembly confirms
the revival path RW 0x781619 and RW 0x781626, after RespawnUpdate's initial-spawn
byte is set and before Gandalf/Aragorn science handling:

```cpp
// RW 0x781617..0x781632 (both getter calls retained in retail).
if (obj->getDrawable())
    obj->getDrawable()->rva00274176(true); // RW 0x67449C
```

The callee's donor is
`Code/GameEngine/Source/GameClient/Drawable_rva00274176.cpp`:
`Drawable::rva00274176(bool immediate)`, BFME2 0x674176, mapped tier A to
RW 0x67449C. It returns only when neither dirty (+0x443) nor immediate;
applies pending-clear and pending-set masks to current conditions at +0x258;
iterates the interface vector +0x158/+0x15C, calling
`replaceModelConditionState(&state, immediate, 0)`; then clears dirty.
The true argument matters even if no flags changed. No simulation arithmetic.

## Port disposition

The engine deliberately does not keep a render-thread Drawable pointer in Object.
It uses ClientEventRecorder and DrawableManager's object-ID lookup. Adding a raw
getter would violate that separation. `Object::flushDrawableModelConditions()`
already models the **false**, dirty-only call; it cannot stand in for the forced
true call. The recorder skips clean objects, Drawable::flushModelConditions skips
clean flags, and the draw-module transition API must preserve immediate=true.

S-852 is narrowed from an unidentified AI/getter pair to the identified missing
**forced client model-condition refresh on hero creation**. No new simulation
behavior is introduced. Remaining work: carry immediate through the event and
draw-module path, emit after the RespawnUpdate assignment, and test a clean and a
dirty drawable with immediate=true (including state re-entry). Do not infer that
every Object has a drawable from this getter: it merely returns the nullable field.
