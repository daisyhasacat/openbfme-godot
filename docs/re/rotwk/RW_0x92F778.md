# RW 0x92F778 — Palantir rank and remaining-time selection (S-1955)

## Evidence and provenance

Read in Ghidra 12.1.2 against the supplied image, with disassembly for register
ownership and the LifetimeUpdate interface. The image has modified `stxt*`,
`.mackt`, `.danetta` sections (S-001): this is not an independent clean-retail
parity claim. Private raw analysis and binary bytes are not committed.

The map pairs RW 0x92F778 with BFME2 0x928CEB (tier B, edited),
`PalantirObjectProgress.cpp::rva00528CEB`. The control-bar/Palantir update
RW 0x9305CE obtains one result for its context object or compares the results
of the current selection; mismatched triples suppress the interface.

## Recovered result and priorities

Result fields are three consecutive words: mode (0 rank, 1 timer, 2 none),
rank, float progress. Initialize all three to zero.

1. RW 0x92F7BD..0x92F7F6: `LifetimeUpdate` exists and its byte +0x28 is zero:
   select start +0x24 and death +0x20.
2. Otherwise, RW 0x92F7F8..0x92F847: object status 0x3E
   (`TEMPORARILY_DEFECTED`): `TemporarilyDefectUpdate` with nonzero end +0x20
   selects that end and start +0x24. **Even a missing/zero timer here prevents
   the following HIDDEN branch.**
3. Otherwise, RW 0x92F849..0x92F8BC: status 0x10 (`HIDDEN`), with
   `ToggleHiddenSpecialAbilityUpdate` and data +0xD0 (`ShowPalantirTimer`):
   start is its virtual slot 0x64 (`hideFrame`, RW 0x69AE14), end is unsigned
   start + data +0x7C (`EffectDuration`, logic frames).

For a timer, end <= start gives mode 2. Otherwise (RW 0x92F8C8..0x92F935):

```cpp
result.progress = (float)(unsigned)(end - now) / (float)(unsigned)(end - start);
if (now > end || result.progress < 0.0f) result.progress = 0.0f;
else if (result.progress > 1.0f) result.progress = 1.0f;
```

Unsigned differences are converted by signed `fild` followed by 2^32 correction
where needed. The division result is stored to float before the clamp.

Otherwise (RW 0x92F93A..0x92F976), choose the displayed template from
RW 0x69194E, falling back to the real template. Its byte +0x5F7 is
`IsTrainable`. A false byte or a false RW 0x9D2437 rank query gives mode 2.
With an override, successful rank becomes **1** but experience progress stays
the real object's value. This is what the bytes do; the port does not conceal
additional information on its own initiative.

## RW 0x69194E — displayed disguise template

RW 0x46E918 tests model condition **300, DISGUISED**, in the object's bitset
at +0x10C, not the template KindOf. The map's donor name `Object::isKindOf`
is misleading here; the receiver and bitset offset prove this distinction.

Only a local player that is neither observer (+0x35A) nor defeated (+0x754)
and whose relationship to the object's **team** (+0x31C) is ENEMIES (0)
gets an override. RW 0x6A87F5 negates RW 0x6AAC52's active-player predicate;
RW 0x6ADBEB is the team-aware relationship query, not merely owner equality.

* DISGUISED: the first `SpecialDisguiseUpdate` supplies
  `DisguisedAsTemplate_EnemyPerspective` (data +0xDC, getter RW 0x8B4440).
* Otherwise: RW 0x68FBD3 walks the object's StealthUpdate vector
  (+0x4D4..+0x4D8), taking the **first upgrade-eligible module**. Its
  template +0x3C is the override; null does not search subsequent modules.
  RW 0x7761ED checks the object's upgrade mask (+0x28C) against required
  (+0x48) and forbidden (+0xD8) masks via RW 0x73BE09: every required bit,
  no forbidden bit. It does not require the halfway drawable swap flag.

## Lifetime waiting is explicit state

The constructor RW 0x7A7EE6 copies WaitForWakeUp (data +0x10) to module
+0x28 and zeros the frame pair. RW 0x7A7E41 can set a lifetime range
**without clearing this byte**. Therefore inferring waiting from zero frames
was wrong. At RW 0x7A7E6F the update-interface receiver is module +0x10:
`cmp [esp+4],0x3fffffff` ignores a forever notification; otherwise
`mov byte [ecx+0x18],0` clears module +0x28 and RW 0x7A7E60 reapplies the
data's own lifetime range. This override now participates in the existing
`wakeFromInterface` call used by ActivateModuleSpecialPower.

## Port and coverage

The Palantir reads these fields through module accessors. Selection fast-path
reuse excludes timed and disguised objects: equal experience is not equal
remaining lifetime or equal displayed rank. The new waiting byte is read only
by the client presentation, so it does not add a word to the existing state
hash; the interface wake override can change scheduling when a LifetimeUpdate
is activated and is explicitly reported as a behavior change.

`hud5 recovered*` retail regressions cover Wormtongue's cloak and defection
priority, mixed selection, enemy Eowyn rank and unchanged progress, allied and
defeated viewers, and a retail WaitForWakeUp template whose range was set before
its interface wake. Existing HUD rank and module tests remain regression gates.
No expected pinned vectors are edited. Rendered Godot parity is not claimed.
