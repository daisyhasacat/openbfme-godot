# RotWK `0x807848`: help-provider guards and auxiliary help

## Provenance

Recovered with the local Ghidra service and RotWK-to-BFME2 map from the supplied
modified image, which contains `stxt*`, `.mackt` and `.danetta` sections. No
independent clean-retail checksum was established. These are address-level
findings, not a claim of clean RotWK 2.01 parity. No binary artifacts are included.

## Owner, callers and order

`ControlBar::showHelp` owns the cloned provider at `+0x2AC` and the per-frame
hover mark at `+0x21C`. The command-provider wrapper is `RW 0x807A00`; the
provider's vslots are release, clone, delay and compose. `RW 0x8075E4` returns
the command window's `+0x1C8` delay, or **zero** for a null window.

The recovered order in `RW 0x807848` is:

1. Return when `InGameUI` vslot `+0x1BC` reports tooltips disabled, or when
   `ScriptEngine` (`RW 0xDE3BAC`) has `+0x1A204 >= 0` (the end-game timer).
   Only the timer half of this early guard is implemented in this change.
2. Compare the supplied and retained providers (`RW 0x8075A3`). An equal
   provider marks the frame. Return if already consumed or if unsigned
   `timeGetTime() <= hoverStart + providerDelay`.
3. For an elapsed equal provider, set the consumed flag **before** testing
   `InGameUI` vslot `+0x17C`: the `+0x810` mode flag must be zero, and
   `RW 0xDEA328 == 0`. Only then compose via `RW 0x807676` and give the result
   to the Palantir (`RW 0x6D4728`). The port represents the latter condition
   with the `TheDisconnectMenu` screen lifetime; a registered
   `DisconnectScreen::InitGadgets` suppresses composition after the consumed
   mark, so the same hover does not retry. The separate vslot `+0x1BC` tooltip
   policy and the `+0x810` mode gate remain unported.
4. For a different provider while the help box reports shown, release the
   retained provider with `RW 0xA0CB16`, then request hide-soon (`RW 0x6D473D`).
   Otherwise clone/store the incoming provider, mark the frame, reset the
   hover clock and clear the consumed flag. Without a Palantir, release instead.

`RW 0xA0CB16` nulls the owned pointer before releasing its old object. The port's
value provider therefore clears both its presence flag and identity immediately,
instead of waiting for the next unmarked frame to drop the provider.
The movie's shown predicate is state 3, not its state-4 hide countdown; the
existing five-update hide and replacement behavior is preserved.

### Early timer guard, disconnect-menu lifetime, and unresolved UI mode gate

The early end-game timer gate is ported. The W3D InGameUI constructor
`RW 0x48E889` installs `RW 0xBDD9B0`. Its `+0x17C` entry is `RW 0x48E916`,
the seven-byte getter of byte `this+0x810`. This byte is a late mode gate, not
the engine/script input-enabled flag; its exact owner and callers remain open.
The RotWK vtable's slot 94 is `RW 0x69B6A8`, slot 95 is `RW 0x48E916`, and slot
82 is `RW 0x69B5ED`. The setter at `RW 0x69B6A8` stores `+0x810` and on a
false-to-true transition clears drag, selection, cursor and mode state. The
donor `InGameUIInputModes.cpp` labels slot 94's name unknown; this does not
establish that `+0x810` is an input-enabled field. The engine/script input
gates are separate flags at `+0x15` and `+0x16`, written through slot 82.

The global at `RW 0xDEA328` is `TheDisconnectMenu`. `get_xrefs_to` identified
its writers as `RW 0x91988F` and `RW 0x919158`; both explicitly
register/unregister `DisconnectScreen::InitGadgets`. The map identifies
`RW 0x91988F` as the tier-B `AptDisconnectScreen::AptDisconnectScreen` and
`RW 0x919158` as the tier-A `AptDisconnectScreen::~AptDisconnectScreen`.
The port uses `WindowManager::hasScreenRef("DisconnectScreen::InitGadgets")`,
the lifetime-equivalent registration in the same screen/window manager:
`GodotAptPlayer` owns that manager, the registration exists for the whole
screen lifetime including before movie initialization, and `AptScreen` clears
it during destruction. The guard is checked after the consumed mark, matching
the recovered dismissal-without-retry ordering.

The `+0x1BC` entry is `RW 0x69BB14` (a function boundary missing from the map's
coarser enclosing row). Direct disassembly proves:

```cpp
// RW 0x69BB14, descriptive field names where original names are unproven.
bool InGameUI::areTooltipsDisabled() const {
    if (!TheGlobalData->byteDD0) return true;
    if (TheLivingWorldLogic && TheLivingWorldLogic->query441E4A()) return false;
    return TheGameLogic->getFrame() < tooltipDisableUntil; // this + 0x7EC
}
```

The BFME2 donor `InGameUI_Rva0029B04D.cpp` corroborates the setter/clearer/deadline
shape. The RotWK-only Living World query is **not** assumed identical to the
BFME2 selection-lock predicate. The global setting, setter callers and Living
World query need their own port; the vslot `+0x1BC` tooltip policy is not
implemented.

The port implements the end-game timer and the `TheDisconnectMenu` lifetime
check among these guards. The timer is owned by `EndGameController` in this
engine, rather than ScriptEngine (existing PLAY-1 difference); the Godot HUD
obtains that controller's timer through its host callback. Both positive and
zero timers suppress new help.

## Spellbook and idle-builder providers

`RW 0x931698` registers 24 spellbook hover keys using
`Palantir/<DotPath2SlashPath(clip)>/Spell<n>/` (one-based index). The callback
at `RW 0x9310AD` adjusts to its owner/index payload and jumps to `RW 0x930DC4`:
read the displayed slot's button at `owner + 0x54 + 0x14*index`, and, when
nonnull, call `RW 0x807A00(nullptr, button)`. The help is ordinary command help,
not the spell-store pending-purchase proxy. Empty displayed slots have no help.

`RW 0x92DDE7` registers sixteen `Hero<n>/` keys for the hero movie through
`RW 0x92B319`. `RW 0x92BF34` checks the slot's builder byte at `+0x16`. When
set, it finds `NonCommand_SelectNearestBuilder` and calls the same null-window
command-help wrapper. When clear, a non-sentinel hero slot uses its object's
ID to construct the separate object-help provider (vtable `RW 0xC130E8`).

The port uses the current movie slot mapping and WindowManager's hover path.
The inherited hover-path extraction from the Apt button's parent remains an
**INFERENCE** (S-173); tests exercise the actual mounted movie, rather than
inventing alternate paths. The registry key includes a trailing slash, while
`WindowManager::hoverPath()` returns the parent clip path without that final
slash. Null-window providers use delay zero.

## Remaining S-2703 blockers

The hero provider's `RW 0x8EBC61` builds object help including custom/Create-a-Hero
name, horde veteran-member text, rank, maximum health, melee/ranged damage,
powers, battles fought and description. The current `CommandButtonHelp::Text`
and renderer represent command name/cost/shortcut/description, not that object
help model. A dedicated object-help model/renderer and its missing record/stat
contracts are required; substituting a hero's build-button tooltip would be wrong.
The late `+0x810` mode gate and its owner/callers, the vslot `+0x1BC`
tooltip-disable policy, and full hero object help remain open.
